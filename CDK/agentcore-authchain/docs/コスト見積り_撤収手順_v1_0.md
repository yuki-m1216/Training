## 2. 本検証の想定使用量と概算（V0〜V4 通し、約 2 週間）

| DynamoDB／Lambda／Identity | 無料枠・極小 | **≈ $0** |

## 4. 撤収手順（検証完了後。**実行は必ずユーザー確認のうえ**：§6）

### 4-1 事前確認
1. `docs/証拠マップ_v1_0.md` と各検証ログが揃っているか（消すと再取得できない実測が無いか）
2. `out/` のトークン・SAML 実物は検証ログにマスク済みで転記済みか → ローカルからは削除

### 4-2 CDK スタックの削除（依存の逆順）
```bash
cd CDK/agentcore-authchain/cdk
export AWS_PROFILE="Y_admin"
npx cdk list                              # スタック一覧を確認
npx cdk destroy AuthChainRuntimeStack      # Runtime（Gateway の URL を環境変数で持つだけなので先に消してよい）
npx cdk destroy AuthChainGatewayStack      # Policy 7 本 → Gateway（紐付け解除）→ PolicyEngine の順に CFN が逆依存で消す（V4）
npx cdk destroy AuthChainIdentityStack     # UserPool（ローカルユーザー a/b/c を含む）／DynamoDB。removalPolicy DESTROY 前提
```
- Cognito ドメインはプールと同じスタックなら一緒に消える。ドメイン削除は伝播に数分かかることがある
- DynamoDB は `removalPolicy: DESTROY` にしておく（検証用）。RETAIN のままだとテーブルが残る

### 4-3 消し忘れチェック（cdk destroy では消えないもの）
| 対象 | 確認コマンド／場所 | 対処 |
|---|---|---|
| S3 の CDK アセット（Runtime コード zip・Lambda zip。ブートストラップバケット `cdk-hnb659fds-assets-<acct>-ap-northeast-1` に残る） | `aws s3 ls s3://cdk-hnb659fds-assets-<acct>-ap-northeast-1/` | 放置可（極小）。掃除するなら `cdk gc`（要確認）。**兄弟プロジェクトの資産と同居しているので削除対象を絞る**。ECR は本検証では使わない（仮決め #13） |
| CloudWatch Logs グループ（Lambda 自動作成 `/aws/lambda/...`、AgentCore `/aws/bedrock-agentcore/...`、Cognito） | `aws logs describe-log-groups --log-group-name-prefix /aws/lambda/AuthChain` 等 | 削除 or 保持期間を短く（CDK 側で `LogGroup` を明示作成＋`RemovalPolicy.DESTROY` にしておけば destroy で消える） |
| Cognito ユーザープール（RETAIN の場合） | コンソール／`aws cognito-idp list-user-pools` | 手動削除 |
| DynamoDB テーブル（RETAIN の場合） | `aws dynamodb list-tables` | 手動削除 |
| X-Ray リソースポリシー `AWSLogDeliveryWrite20150319`（V3 で TRACES 配信の作成時に配信サービスが自動追加。CDK 管理外） | `aws xray list-resource-policies` | 他に X-Ray 配信を使うものが無ければ `delete-resource-policy`（要確認） |
| Bedrock のモデル契約 `anthropic.claude-haiku-5-5`（V5b で作成。アカウント単位、CDK 管理外。待機コスト無し） | `aws bedrock get-foundation-model-availability --model-id anthropic.claude-haiku-5-5` | 不要なら `aws bedrock delete-foundation-model-agreement --model-id anthropic.claude-haiku-5-5`（ほかで使っていないことを確認してから） |
| 一時アプリクライアント（V3 の壊す実験） | `aws cognito-idp list-user-pool-clients` | V3 終了時に削除済みであること |
| Entra 側 | **SAML** エンタープライズアプリ `cognito-authchain-verify`（V1'-c で AWS 側は撤去済、Entra 側は残置）、**OIDC** の App registration（ランブック v2.0。クライアントシークレットも一緒に消える）、User-A/B、（専用に作ったなら）テナント | 削除。テナント削除は「ディレクトリの削除」（前提条件のクリアが必要） |
| Secrets Manager `authchain/entra-oidc-client-secret`（CDK 管理外。ランブック v2.0 §3 で手動作成） | `aws secretsmanager describe-secret --secret-id authchain/entra-oidc-client-secret` | `delete-secret --force-delete-without-recovery`（要確認）。残すと $0.40/月 |
| ローカル | `out/`（トークン・SAML）、一時 DOCKER_CONFIG、`docker image rm tonistiigi/binfmt`（任意）、`docker run --privileged --rm tonistiigi/binfmt --uninstall arm64`（任意） | 削除 |
