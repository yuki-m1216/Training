## 目的（2 軸）
1. 要件固有：組織属性の正規化 → エージェント認可マスタ → `agents` クレーム → Runtime 入口認証 → 同一 Bearer 透過 → Gateway Policy（Cedar）の連鎖を実測で確かめる

- **V4 の主な実測**（`検証ログ_V4`）：
  - Gateway に PolicyEngine `authchain_engine` を **ENFORCE** で紐付け。P1（permit：`company_code == "TESTCO"`）、P2（forbid：`department_code == "ADMIN1"` かつ `context.input.note like "*delete*"`）、P3・P3a〜d（`agents` の探り、ポリシー単位 LOG_ONLY）

  - **配列クレームは空白なしの JSON 配列文字列の tag**（`["admin-only","inspect-headers"]`）。要素一致は `like "*\"inspect-headers\"*"`
  - **ポリシー単位 LOG_ONLY**（`CfnPolicy.enforcementMode`）は評価するが判定に数えない。メトリクス `LogOnlyMatches`、スパン `log_only_matched_policies`
  - LOG_ONLY の観測はメトリクス（`AllowDecisions`／`DenyDecisions` の `Policy` 次元、`DeterminingPolicies`／`NoDeterminingPolicies`／`TotalMismatchedPolicies`）。`tools/call` のスパンは `LOG_ONLY_ASYNC` のみ。ENFORCE では `AgentCore.Policy.AuthorizeAction` スパンに判定・理由・`determining_policies`。スパンに `sub` は無い
  - **Policy の拒否は HTTP 200 の JSON-RPC `error` -32002**（`Tool Execution Denied … [理由]`。公式の `isError=true` とは違う）。-32002 は Gateway 入口の 403 と同じコード
  - **agent.py は Policy 拒否で `McpError` を処理できず落ちる**（Runtime は 200＋`{"error": "ExceptionGroup…"}`）。修正は V5 で行う（ユーザー判断：B）。agent.py のコメント「isError=true で返る」は誤り
  - 壊す実験：`GetPolicyEngine` を外しても約 9.5 分は全拒否にならない（予想外れ）。P1 削除は即時にデフォルト拒否
  - Policy 紐付け後は**トレース文脈なしの呼び出しにもスパンが出る**（原因未確定）→ agent.py への `traceparent` 追加は不要と判断

## 進め方のルール
- 核心ステップは「予想 → 実測 → 照合」（予想は Claude が代行可）。周辺ステップは質問せず進める。課金・削除・IAM・グローバル設定の変更は事前確認
- `export AWS_PROFILE="Y_admin"` は毎セッション確認。テストは書かない。一度に 1 変更。公開リポジトリのマスク規約（`<tenant>`/`<ACCOUNT>`/`<PoolId>`/`<ClientId>`/`<user>@<tenant>…`、Gateway ID は `authchain-gateway-<id>`、エンジン・ポリシーは `<name>-<id>`、ターゲットは `<targetId>`）
- 設計判断は「要件固有／汎用（ベストプラクティス準拠）／簡略化」を明示。公式推奨からの逸脱は理由付きで `整理_システム全体像` §5 に記録し、実装を変えるかは各 V の diff 提示時に個別確認
- 再ログインは `get_token.py --user <label> [--idp EntraOIDC]`（`python3 -u` でバックグラウンド、シークレットウィンドウ）。ローカルユーザーは `--idp` を付けずユーザー名とパスワードの欄で。アクセストークンの更新だけなら refresh グラント（ブラウザ不要、`ツール使い方` §4）
