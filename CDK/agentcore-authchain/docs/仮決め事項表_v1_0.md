# 仮決め事項表 v1.0

対象プロンプト：AgentCore認証チェーン検証実装 v1.1（§3 を分離）。本番設計書で未確定の項目を以下の仮決めで進め、検証で得た実測値を「実測結果」列に追記する。仮決めからの逸脱は実装前に要相談（§0-1 規約7）。

| 14 | **エージェント認可マスタの置き場（追加要件 2）** | **別テーブル `AgentEntitlement`**（pk `COMPANY#<company_code>` / sk `AGENT#<agent_key>` / `departments` String Set 任意）。既存の正規化マップは現状維持 | DynamoDB 公式「運用要件が独立・明確な運用境界が必要ならマルチテーブル」に合致（読む主体・所有者・バックアップ方針・IAM が正規化マップと異なる。1 回の Query で両方を引く利点がない）。**2026-08-29 ユーザー承認（計画書 §7-B）** | V2-1（2026-08-30）：TableV2（pk/sk、オンデマンド）＋シード 2 行（`TESTCO/inspect-headers` 全部門、`TESTCO/admin-only` は `{ADMIN1}`）をデプロイ。Pre Token Gen ロールには **`dynamodb:Query` の 1 アクションのみ**（`grantReadData` 不使用）。Query 1 回＋Lambda 側の部門フィルタで 391 ms（検証ログ V2） |
| 15 | **エンタイトルメントの評価点（追加要件 2／3）** | **トークン埋め込み**：Pre Token Gen が `agents`（配列）を両トークンに注入 → Runtime の JWT オーソライザ `customClaims`（`agents` STRING_ARRAY CONTAINS `<agent_key>`）で入口拒否。`agent_key` は一致値パターン `[A-Za-z0-9_.-]+`（コロン不可） | Cognito V2_0 は配列値を公式サポート。Runtime 入口で止まりエージェント実装・IAM に依存しない。失効はトークン寿命単位（即時失効が要れば実行時照会を併用）。**2026-08-29 ユーザー承認（計画書 §7-C）** | V2-1（2026-08-30）：両トークンに **`agents: ["inspect-headers"]` が配列のまま注入**された（V2_0 の配列サポートを実測）。部門不一致の `admin-only` は除外、OTHERCO は非注入。併せて `upn`（`preferred_username`）をアクセストークンにも注入。Runtime 側の CONTAINS 判定は V2a で実測 |
