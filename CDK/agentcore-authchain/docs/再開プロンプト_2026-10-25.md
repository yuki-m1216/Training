## 進め方のルール
- 核心ステップは「予想 → 実測 → 照合」（予想は Claude が代行可）。周辺ステップは質問せず進める。課金・削除・IAM・グローバル設定・法的な合意（モデル契約など）の変更は事前確認
- `export AWS_PROFILE="Y_admin"` は毎セッション確認。テストは書かない。一度に 1 変更（依存も「ロックの差分が対象だけか」を見る）。公開リポジトリのマスク規約（`<tenant>`/`<ACCOUNT>`/`<PoolId>`/`<ClientId>`/`<user>@<tenant>…`、Gateway ID は `authchain-gateway-<id>`、エンジン・ポリシーは `<name>-<id>`、ターゲットは `<targetId>`）
- 設計判断は「要件固有／汎用（ベストプラクティス準拠）／簡略化」を明示。公式推奨からの逸脱は理由付きで `整理_システム全体像` §5 に記録し、実装を変えるかは各 V の diff 提示時に個別確認
- Runtime のコード変更は、deploy 前に手元から `agent.invoke` を直接呼んで Gateway／Bedrock の実物で確かめる（uv、Python 3.13、`--with-requirements runtime-code/requirements.txt`。手元の Python は 3.10 なので `except*` は uv の 3.13 で）
- 依存を足すときは公開から 1 週間以上の版、PyPI provenance と OSV を確認してからロックへ
- 再ログインは `get_token.py --user <label> [--idp EntraOIDC]`（`python3 -u` でバックグラウンド、シークレットウィンドウ）。アクセストークンの更新だけなら refresh グラント（ブラウザ不要、`ツール使い方` §4）
